Scope & Method

This report reviews the flare-local-inference SDK and runtime architecture across all seven components. Evidence is drawn from the repository files supplied for this review: AGENTS.md, README.md, pyproject.toml, docs/core-design.md, docs/runtime-package-design.md, docs/model-preparation.md, flare/Cargo.toml, helios/Cargo.toml, selene/Cargo.toml, plus CONTRIBUTING.md, SECURITY.md, docs/cli-design.md, docs/api.md, flare/src/cli.rs, .gitattributes, and docs/PR_159_WINDOWS_N1X_SUMMARY.md.

No test suite, build, or GPU workload was executed during generation of this report. Findings are a static document and code review. Any statement about runtime behavior, performance, or platform execution not directly established by a cited file is labeled unverified and treated as a review hypothesis. Nothing here should be read as a qualification result.

1. Repository Structure

Flare splits into a Python preparation layer and a Rust serving layer with a strictly ordered dependency direction: flare → Helios and heliopause → Helios, with Helios depending on neither preparation tool (docs/runtime-package-design.md).

ComponentRole (cited)Evidence
flarePublic serving CLI; links Helios, loads a package, runs the server.flare/Cargo.toml (deps flare-helios with runtime-package, server), flare/src/cli.rs
heliosRust runtime library; rebuilds a package into a live CUDA context and serves it; no CPython dependency.helios/Cargo.toml, docs/core-design.md §3
heliopauseCPython extension imported by Ignition; owns preparation storage, export recording, graph serialization, signed package publication.docs/runtime-package-design.md §1, pyproject.toml (flare-heliopause path source)
ignitionPython model preparation command (export, debug-serve, bench, convert); recipes own model composition.pyproject.toml, docs/cli-design.md §2, AGENTS.md
seleneRust library for prefix-cache pool / shard record transport (tokio, tonic, rustls; optional rdma).selene/Cargo.toml
selene-managerManager-side counterpart referenced as a dev-dependency for Helios tests on unix.helios/Cargo.toml ([target.'cfg(unix)'.dev-dependencies] flare-selene-manager)
eosLow-level platform/storage crate depended on by both Helios and Selene.helios/Cargo.toml, selene/Cargo.toml (flare-eos = { path = "../eos" })

Feature-gating is deliberate: Helios exposes runtime-package, frontend, images, grammar, server, roce, rdma as opt-in cargo features (helios/Cargo.toml). Flare forwards roce/rdma to Helios (flare/Cargo.toml). Python preparation pins a narrow interpreter window (requires-python = ">=3.12,<3.13") and exact dependency versions (pyproject.toml).

3. Outstanding Items

Each item below traces to a cited file or named component; no item asserts a runtime defect that the evidence does not support.

#Outstanding itemTrace / evidence
1Full-model relocation lacks complete pointer/tensor-map bindings for opaque resources; loader accepts typed relocations but exporter preserves addresses.docs/runtime-package-design.md §8 Open items
2sm_120 TMA tile path reserves ~3.6 GiB device memory per context; memory plan not yet accounting for it once identified b12x kernels use it.docs/runtime-package-design.md §8
3Legacy allocator-segment packages are allocation-order sensitive and duplicate weights per TP size; migration to payload-based packages incomplete for unsupported mappings.docs/runtime-package-design.md §8
4Derived TP materialization has byte-exact fixtures but no full-model TP2 reshard qualification.docs/runtime-package-design.md §8
5Windows package immutability vs. directory rename: sealed files open with FILE_SHARE_READ only, so an open handle blocks rename (authenticated_handles_survive_rename_and_replacement).docs/PR_159_WINDOWS_N1X_SUMMARY.md (Open Architectural Tradeoff, eos/src/windows.rs)
6Native Windows GPU export and serving were not exercised; only cross-compile, cargo check, and Linux validation reported.docs/PR_159_WINDOWS_N1X_SUMMARY.md (Validation)
7Peer storage cannot pass descriptors on Windows (DupFd unavailable); explicit runtime error on cudaIpcGetMemHandleBytes.docs/PR_159_WINDOWS_N1X_SUMMARY.md (commit cf97a93b, ignition/preparation/peer_storage.py)
8RDMA data channel and RoCE remain labeled experimental in cargo feature comments.flare/Cargo.toml, helios/Cargo.toml, selene/Cargo.toml (rdma)
9Debug modes (ignition debug-serve, --direct, --eager) are diagnostic-only and explicitly unsuitable for performance comparison.AGENTS.md, docs/model-preparation.md
10Performance acceptance (native replay within 5% of harness floor, bandwidth bound ~3.9 ms/token at 1.79 TB/s) is a requirement, not a measured result in the cited files.docs/core-design.md §5 Performance acceptance
11Compression of executable resources (zstd level-3) is not confidentiality; signed packages are executable input, not sandboxed code.SECURITY.md (Model package integrity)
12Download-cache reclamation gaps: unleased .flare-hub-staging-* directories and interrupted post-install cleanups remain until gc --downloads; platforms without inode identity over-count retained bytes.docs/cli-design.md (Local model management)
13Capture of a new graph operation family requires explicit owner approval; not a defect but a governance obligation for contributors.AGENTS.md (Architecture and ownership)
