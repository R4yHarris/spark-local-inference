3. Per-File Analysis

3.1 .gitattributes

Adds ignition/recipes/*/assets/*.jinja text eol=lf after existing -text rules for third_party/rust/** and packaging/license-supplements/**. This preserves chat-template bytes that feed digests and embedded template parsing across core.autocrlf checkouts. supplied fact The rule is narrow and does not alter license/notice handling. Residual risk: any future template directory outside the pattern would silently lose LF pinning. reviewer inference

3.2 eos/src/windows.rs

Replaces PhysicalBytesPerSectorForPerformance with PhysicalBytesPerSectorForAtomicity in the check_alignment loop over [LogicalBytesPerSector, PhysicalBytesPerSectorForAtomicity], with a comment that the performance size is a hint. The file also holds direct_read_guard (section 4). Tests exercise guard immutability and cancellation drain. reviewer inference: atomicity is the safer unbuffered-I/O alignment source, but 4K-sector devices where atomicity is not a divisor of 4096 would be rejected as Unsupported.

3.3 heliopause/src/export/capture.rs

Selects the NVML soname by cfg!(windows) (nvml.dll vs libnvidia-ml.so.1). The surrounding module dynamically loads nvcuda.dll on Windows via libloading::os::windows, and validates graph spans, relocations, and kernel argument layouts before export. unverified: no GPU export was run; correctness of NVML naming on N1X drivers is a review hypothesis.

3.4 helios/src/package/naming.rs

Introduces GB10_DEVICES = [0x2e12, 0x2e03] and switches platform_from_pci to contains. Naming stays display-only; identities remain content hashes and signatures. Tests loop over GB10_DEVICES and reject non-NVIDIA ids (0x2bbc_1af4) and unknown devices (0x1e02_10de). The unknown-device-* fallback avoids guessing from SM architecture. Strong test coverage of the boundary.

3.5 helios/src/runtime_package/protection.rs

Resolves asset_path to the primary container when the relative name is empty, and adds asset_paths_read_initializer_bytes_in_directory_and_packed_packages covering directory and packed forms. The module carries signature verification (ring), PackageClaim parsing for format-6 and payload containers, source_valid restricting official sources to https://huggingface.co/<namespace>/, and an open-file preflight. reviewer inference: preflight_open_files returns Ok(()) on #[cfg(windows)], so the descriptor budget is unenforced on the platform this PR targets.

3.6 ignition/patches/__init__.py

Restructures apply() to skip absent Triton only when sys.platform == "win32", keep Torch mandatory, preserve exact versions (2.14.1+cu132, 3.8.0), skip hunks for missing packages, and retain atomic replacement via os.replace with permission preservation and imported-module refusal. Hunk parsing restricts targets to b/torch/_inductor/ or b/triton/runtime/build.py. reviewer inference: the Windows exemption is correct for Torch's bundled Triton on some builds, but the error message for missing Triton on non-Windows still surfaces the generic dependency hint.

3.7 ignition/preparation/peer_storage.py

Guards DupFd import and raises RuntimeError("peer storage requires POSIX descriptor passing") in cudaIpcGetMemHandleBytes. The VMM mapping path uses cuMemRetainAllocationHandle/cuMemExportToShareableHandle with careful finally cleanup. unverified: collective preparation on Windows is explicitly unsupported here; the import-only tolerance is documented in the summary.

3.8 selene/Cargo.toml

Adds Win32_Security_Cryptography to the existing windows-sys 0.61 feature set for cfg(windows). No new crate; supply-chain surface is unchanged apart from the feature flag. supplied fact

3.9 selene/src/shard.rs

Splits nonce() into #[cfg(unix)] /dev/urandom and #[cfg(windows)] BCryptGenRandom with BCRYPT_USE_SYSTEM_PREFERRED_RNG, returning a mapped error on negative NTSTATUS. Framing enforces FRAME_LIMIT (64 MiB), non-blocking reads, bounded writer backlog, and stall detection. reviewer inference: no #[cfg(not(any(unix, windows)))] fallback exists, but the crate targets only those platforms.

3.10 tests/preparation/test_inductor_patches.py

Parametrizes dependency-version failures over linux/win32 and adds test_missing_dependency_is_allowed_only_for_triton_on_windows, restricting sys.path to the fixture installation. Covers idempotence, hardlink breaking, permission preservation, concurrency, and parity with system patch. Strong behavioral suite.

4. Open Tradeoff: eos::windows::direct_read_guard

direct_read_guard calls reopen_direct(file, FILE_SHARE_READ), omitting FILE_SHARE_WRITE and FILE_SHARE_DELETE, whereas direct_reopen uses all three. The guard's doc comment says it keeps a package immutable without retaining a buffered handle alongside direct readers.

BehaviorFILE_SHARE_READ only (current)Adding FILE_SHARE_DELETE
ImmutabilityWriters and deleters get ERROR_SHARING_VIOLATION; enforced by the OS.Write still excluded, but delete/rename becomes legal while open.
Directory renameBlocked while any guard handle is open; authenticated_handles_survive_rename_and_replacement fails on Windows. supplied factRename proceeds; handles keep resolving to the old file identity.
Failure modesPackage cache commit/rename paths fail under live readers; retries needed. reviewer inferenceDeletion of a live file is deferred; sealed-attribute semantics must be re-checked; path-based reopen may see a replacement file.
Test coveragedirect_package_guard_preserves_immutability_after_buffered_reader_closes asserts the violation on write and remove.No test in supplied evidence.
Recommendation: reviewer inference Keep FILE_SHARE_READ for the immutability guarantee, but restructure cache commit to rename before opening guards (stage under a temp name, guard, then publish by directory rename of a sibling that holds no guarded handles), or adopt a two-phase publish where the guard is acquired after the rename. Document the constraint in eos/src/windows.rs and add a Windows-only test mirroring authenticated_handles_survive_rename_and_replacement. Do not simply add FILE_SHARE_DELETE without re-proving sealed-package integrity.
